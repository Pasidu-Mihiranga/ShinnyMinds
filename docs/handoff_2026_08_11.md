# Handoff — 11 Aug 2026

A long session on mobile input, the mission camera, the light UI, and the open-world entry
flow. Everything below compiles (both assemblies, clean). **Almost none of it has been seen
running**, because the work was done without opening Unity — so this note separates what was
verified by reading files from what is still guesswork.

---

## 1. The two ending bugs — both now FIXED (verified only by reading, not by playing)

**a. The summary hid itself.** `MissionEndingCard.Awake()` ended with `Hide()`. The component
sits on the card's root, and that root ships **inactive** (`m_IsActive: 0` in MissionUI.prefab),
so `Awake` did not run at load — it ran the instant something activated the object, and the only
thing that ever does is the *last line of* `Show()`. The summary switched itself off in the frame
it appeared and nulled `onRetry` / `onContinue` with it, leaving `MissionRunner.ShowEnding`
spinning on `while (!done)` with the player locked. Pre-existing; reaching an ending is just the
only way to hit it. `Hide()` removed; the prefab's inactive root plus
`MissionUIView.Awake()` → `HideAll()` cover the load case.

**b. Continue left the screen black.** Path A ends `Fade(true, 2.0f)` and nothing ever faded back
in: only the *retry* path cleared the overlay, via `ResetWorld` → `HideAll`. So Continue handed
the player an open world they could not see. `MissionRunner.ShowEnding` now ends the non-retry
path with `ui.Fade(toBlack: false, 0.6f)`, after the camera blend so that happens behind the
black. It is a no-op on the paths that already faded in.

Both were found from a screenshot of a plain black screen. **Neither has been seen working.**

## 2. Verified — read directly in the serialised files

- **Camera culling mask.** `Main Camera` was `m_Bits: 55` = everything up to layer 5 minus
  MapIcon, which **excludes `CameraIgnore` (6)** and `Vehicle` (8). The Stranger's whole
  67-object hierarchy is on layer 6, and 20 traffic objects on layer 8 — all invisible to the
  main camera, visible only to the cutscene camera (mask `0xffffffff`). Now `375`.
- **Camera rig parenting.** `CameraHolder` is a child of the girl at local `(0,0,0)`, so it
  inherited her rotation. That, not the input code, is why the stick and `Face()` swung the view.
- **`Button.normalColor`.** ColorTint *overwrites* the Image colour with it; it was never set, so
  every button rendered white — with near-white labels on them.
- **Path A parallelism.** `RunActions` joins all pending parallel coroutines before a sequential
  one, so with only the Stranger's move marked `Parallel`, Aisha waited out his entire 33 m walk.
- **Actor speed.** GIRL 1 is scale 5; `ActorMover` multiplied by scale (3.5 → 17.5 m/s) while
  `PlayerController` moves her at 6.
- **Mission graph.** Three `Ending` nodes (kind 4) with valid ids, all three endings present,
  `allowContinue: 1` on all of them. The data is not the reason endings fail.
- **Memory stand-ins** carry only a Transform and an Animator — no `ActorMover`, so nothing
  grounded them.

## 3. Unverified or fragile — ranked by how likely it is to bite

1. **The meeting's 5.5 m orbit radius** (`OrbitRadius`, `Mission01Builder`). Derived from marker
   coordinates and an assumed 60° FOV, but the actors are not on their markers when those shots
   fire — that is the whole reason `FramedShotAction` exists. Five beats now share one distance,
   so they may read as five near-identical wide shots. Never seen. Most likely thing here to be
   simply wrong.
2. **`MemoryStage.GroundStandIns()`** copies `ActorMover`'s minimum-lift settling window but
   **omits its 0.2 s sampling delay**. If the Animator has not posed during the first frames, the
   minimum latches near zero and the correction does nothing — Mother floats exactly as before.
   Add the delay if she still floats.
3. **`Vehicle` added back to the culling mask** on the inference that a physics layer should not
   hide things. Nobody confirmed the 20 cars are *meant* to be visible.
4. **`ActorMover` deferring to a sibling `PlayerController`'s speeds.** Correct today; a
   booby-trap if that component ever lands on a non-player actor.
5. **`scratchpad/svg2png.py`** handles only the path commands `jump.svg` / `run.svg` use. No arcs
   (`A`) or quadratics (`Q`) — a third icon using them exits mid-build rather than degrading.
6. **Never play-tested at all:** the light choice panel and summary screen, the mission offer
   zone's 7 m radius and position, Path A's ~11 s walk-off pacing (was 1.9 s before the speed
   fix), and tap-to-advance on a real device — `simulateTouchOnDesktop` on `MobileInput` is the
   only proxy that was reasoned about.

## 5. Compile-checking without opening Unity

No .NET SDK here, but Unity ships Roslyn: `Editor/Data/NetCoreRuntime/dotnet.exe` plus
`Editor/Data/DotNetSdkRoslyn/csc.dll`. Parse `Assembly-CSharp.csproj` /
`Assembly-CSharp-Editor.csproj` for their `<Compile Include>`, `<HintPath>` and
`<DefineConstants>`, write a csc response file, and run it from the project folder (the
HintPaths are relative to it). Newly added `.cs` files are missing from the csproj until Unity
regenerates it, so add them to the source list by hand. Build the runtime assembly first and
pass its output as `-r:` to the editor one.

It catches every syntax and type error. It does **not** catch anything in section 3.
