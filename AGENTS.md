# Shiny Minds - AI Agent Instructions

## Project

This is a Unity 6 educational 3D game for children (ages 8–14).

Tech stack:
- Unity 6
- C#
- Git + GitHub
- Git LFS
- Node/Express + Prisma + PostgreSQL API in `backend/`
- React + Vite parent dashboard in `parent-dashboard/app/`

The game and the dashboard both talk only to the API. Neither reaches the
database directly, and neither holds a third-party API key.

# Working Rules

## Read only what is necessary

DO NOT read the entire project.

Always start from the smallest possible files.

Priority:

1. README.md
2. Docs/
3. Scripts/
4. Requested scene only

Never scan the whole repository unless explicitly asked.

---

## Unity Scene Rules

Never read an entire

- *.unity
- *.prefab
- *.asset

unless explicitly requested.

If a scene is needed:

- search for specific GameObjects
- search for MonoBehaviour names
- inspect only relevant sections
- use git diff when possible

Large Unity YAML files consume excessive context.

---

## Ignore Generated Files

Never inspect or modify:

Library/
Temp/
Logs/
Obj/
Build/
Builds/
UserSettings/
MemoryCaptures/

These folders are generated by Unity.

---

## Code Organization

New gameplay and systems code lives inside:

Assets/Scripts/

Scenes should contain references only.

Avoid embedding large datasets inside scenes.

Prefer building UI in C# over authoring it into a scene. SampleScene.unity is a
17k-line YAML file and is the main source of merge conflicts on this project.
MainMenu.unity holds a camera and one component; MenuUI builds the rest at
runtime.

---

## Secrets

Never add a public string field for an API key. Unity serialises public fields
into the scene, which is how keys used to end up in SampleScene.unity and cause
a conflict on every pull.

Read secrets through:

ShinyMinds.Config.GameConfig

which loads a git-ignored .env or a real environment variable. Add any new
variable to the matching .env.example.

---

## Mission System

Missions are data, not code. The catalogue lives in the database
(backend/prisma/seed.ts), not in if/else chains and not in the scene.

Adding a mission is a seed entry. Progress is reported through:

ShinyMinds.Progress.GameProgressTracker

which records the session, the attempt and each individual decision.

## Git

Never commit:

Library
Temp
Logs
Builds

Respect .gitignore.

---

## Git LFS

Large binary assets should use Git LFS.

Examples:

*.fbx
*.blend
*.wav
*.mp3
*.mp4
*.psd

Do NOT track:

*.cs
*.unity
*.prefab
*.asset
*.meta

with Git LFS.

---

## Coding Style

Prefer:

- small classes
- reusable components
- composition over duplication
- serialized fields instead of magic numbers
- clear variable names

---

## Before Editing

Understand existing architecture.

Make the minimum required change.

Avoid unrelated refactoring.

---

## If Unsure

Ask before making architectural changes.

Never rewrite large scenes automatically.


## Token Optimization

When investigating an issue:

1. Read README first.
2. Read only relevant C# files.
3. Never open large Unity scenes completely.
4. Use targeted search.
5. Prefer git diff over full file reads.
6. Ask before reading any file larger than 500 KB.


Even better: create a project docs folder

Instead of making the AI inspect Unity scenes to understand the project, create:

docs/

    architecture.md

    folder_structure.md

    gameplay.md

    mission_system.md

    scoring.md

    npc_system.md
